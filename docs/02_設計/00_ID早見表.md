# ID早見表 — okada-fit 設計

> **目的**: 設計文書に出てくる ID の意味を1枚で引けるようにする。**レビュワー向けの読解補助**であり、定義の正本ではない。
> **書き方**: ID と名前の対応だけを置く。仕様は書かない。各 ID の正本は右端の列を参照する。

**ID は消さない。** 名前ではなく ID で参照するのは、次の4つの理由による。

| # | 理由 |
|---|---|
| 1 | **位置参照は壊れる。** 「上記の表」「§3の3番目」は、1行足しただけで指す先がずれる |
| 2 | **表記ゆれで追えなくなる。** 「AIメニュー提案」「メニュー提案」「AI提案」が混ざると検索で拾えない |
| 3 | **CI が測定できる。** 受入基準は `FEAT-` にぶら下げて数える。ID が無いと RED 母集合を作れない |
| 4 | **名前が変わっても ID は変わらない。** 機能の中身を改訂しても、過去の参照が全部生きる |

- ID は**不変・欠番再利用禁止**（`../01_要件定義/00_用語定義.md §3`）。
- 使わなくなった ID は削除せず**欠番**として残す。採番を繰り上げない。

- ただし**要件の正本は別ブランチにあり、本ブランチでは確認できない**。
- 別々のルールであるべきなら、片方に新しい ID を振る必要がある。**要件側で確定すること。**

## 4. ST / TR — 状態と遷移

`training_session_details`（トレーニング明細）の実施状態だけが対象である。

| ID | 意味 |
|---|---|
| ST-01 | `not_done`（未実行） |
| ST-02 | `done`（実行済） |
| T01 | （新規）→ ST-01。記録を作った時点 |
| T02 | ST-01 → ST-02。実行済をチェックした時点 |

- 状態を持つのはこの1つだけ。食事記録・入館記録・CSV取込は**一過性イベント**で状態を持たない。
- 正本は `30_データ・IF設計/03_ドメインイベント.md`。

> ⚠️ 要確認（人間判断）: **遷移IDが命名規約に従っていない**（2026-08-08 判明・🟢 低）。

| 項目 | 内容 |
|---|---|
| 規約（`../01_要件定義/00_用語定義.md §3`） | 状態遷移の接頭辞は **`TR-`** |
| 設計文書の実態 | **`T01` / `T02`**（65箇所）。`TR-` は使っていない |
| 本表の扱い | **実態に合わせて `T01` / `T02` と書いている** |

- 規約どおりなら `TR-01` / `TR-02` になる。
- 揃えるなら65箇所の一斉改名が要る。**本ブランチでは実施しない。**
- 規約の正本は要件層（別ブランチ）にあるため、**どちらに寄せるかは要件側で確定すること。**

## 7. ERR — エラー

`ERR-<領域>-<3桁連番>` の形を採る。

| 接頭辞 | 領域 |
|---|---|
| ERR-AUTH | 認証（`ERR-AUTH-001`） |
| ERR-VALIDATION | 入力検証（`ERR-VALIDATION-001`） |
| ERR-AI-* | AI 呼び出し。**連番ではなく語**（`ERR-AI-RATE`／`QUOTA`／`CREDIT`／`TIMEOUT`／`SCHEMA`／`FAIL`） |
| ERR-MACHINE | 器具・種目（FEAT-01） |
| ERR-MENU | メニュー提案（FEAT-03） |
| ERR-TRAINING | トレーニング記録（FEAT-04） |
| ERR-DASHBOARD | ダッシュボード（FEAT-05） |
| ERR-PROFILE | プロフィール（FEAT-06） |
| ERR-MEAL | 食事記録（FEAT-08） |
| ERR-PROTEIN | 残量（FEAT-09） |
| ERR-FOOD | 食品マスタ（FEAT-10） |

- **欠番がある。** `ERR-MENU-003/004/005/006`・`ERR-MEAL-004/008` など。採番は繰り上げない。
- `ERR-AI-*` だけ命名規約から外れている（`06_DB設計規約.md §8` の ⚠️）。
