# 外部連携IF仕様（実装レベル） — 索引＋共通

> **目的**: 外部システム・外部SaaSとの連携を、**実装が迷わない粒度**（認証・エンドポイント・手順・データ構造・エラー）でIF単位に固定する。**連携先が複数ある場合は連携先ごとに1ファイル**へ分割し（`10_{連携先A}連携.md` / `20_{連携先B}連携.md`…）、本READMEを索引＋共通とする。連携先が1つなら本README1枚でよい。
> **書き方**:（記入例は example-suido-fax の対応フォルダ参照）実データは書かず、`{ }` を自プロジェクトの語に置き換える。**契約雛形・IF一覧の正本は `システム基本設計`／`30_データ・IF設計/02_API設計.md`**。**外部ワイヤ（既存API契約）は改変しない**方針を明記し、`EXT-*` でリンクする。

> ⚠️ **Vercel は使わない**（2026-08-07 決定）。クライアントは Flutter、サーバは Supabase Edge Functions。AI は **Edge Function から Google Gemini API を直接呼ぶ**。
> ADR-0001（Vercel AI Gateway 採用）と ADR-0002（Next.js + Mantine）は**この決定と矛盾する**。後継ADRの起票が必要。

## 連携先インデックス
> 📝 ここに連携先とファイル・主なEXT-IDを記載。連携先が増えたら行とファイルを足す（番号は10刻みで挿入余地を残す）。

| 連携先 | ファイル | 主なEXT-ID |
|---|---|---|
| Google Gemini API（モデル `gemini-3.5-flash`） | [`10_GeminiAPI連携.md`](10_GeminiAPI連携.md) | EXT-01 |

外部連携は **EXT-01 の1件のみ**。用途は2つ。

| 用途 | FEAT | 呼び出し元 |
|---|---|---|
| 食事写真 → 栄養価 | FEAT-08 | Edge Function |
| 部位＋器具 → メニュー提案 | FEAT-03 | Edge Function |

呼び出しは同期。第2の連携先は無いため `20_` は持たない。

```
Flutter アプリ → Supabase Edge Function → Gemini API
                        ↑ ここにAPIキーを置く
```

- アプリ→Edge Function の契約は `../../30_データ・IF設計/02_API設計.md` が正本。
- 本フォルダは **Edge Function → Gemini API** の実装ワイヤを担う。
- APIキーは Edge Function の環境変数のみ。**アプリに置かない**（NFR-SEC-02）。

## 共通: 連携の直列化・冪等・再送
> 📝 ここに連携先横断の非機能設計（同時実行制約への直列化・冪等の担保層・再送方針）を記載。{直列化方式（キュー等）／冪等の三層／再送対象と上限（ERR-__・DEC-__）}

| 観点 | 方針 | 理由 |
|---|---|---|
| 直列化 | キューを置かない | 利用者は1人。AI呼び出しは画面操作と1対1で、同時実行がほぼ起きない |
| 冪等 | 冪等キーを持たない | 生成系で毎回課金され、同じ入力でも出力が変わる |
| 二重送信の抑止 | アプリ側でボタンを実行中に無効化 | サーバ側の抑止は未実装（下記の要確認） |
| 再送 | 原則しない。429 のみバックオフ再送 | 従量課金のため、自動再送はコスト増に直結 |
| 失敗時 | DLQ を持たず縮退 | 非同期ジョブが無く、滞留が発生しない |

再送の可否をエラー別に示す。

| ERR-ID | HTTP | 再送 |
|---|---|---|
| ERR-AI-RATE | 429 | する（指数バックオフ） |
| ERR-AI-CREDIT | 402 | しない（永続失敗） |
| ERR-AI-TIMEOUT | 504 | しない（利用者の再操作に委ねる） |
| ERR-AI-FAIL | 500 | しない（同上） |

縮退時は AI 機能のみ止め、記録と閲覧は続ける（NFR-AVAIL-05）。利用者にはトーストで知らせる。

横断方針の正本は `../07_実装共通設計パターン.md`（§3 冪等・§4 リトライ・§5 多重制御）。本書では再定義しない。

> ⚠️ 要確認（人間判断）: Gemini API が落ちたときの代替経路。現行は「縮退のみ」。別プロバイダへの切替を持つなら EXT-ID の追加が要る。

> ⚠️ 要確認（人間判断）: 429 再送の最大回数・初期間隔・打ち切り条件（`[仮]`）と、レート制限の閾値（NFR-SEC-05）。

> ⚠️ 要確認（人間判断）: 二重送信の抑止をアプリ側だけに任せてよいか。連打や再読込での重複呼び出しは課金に直結する。

> ⚠️ 要確認（人間判断）: ADR-0001・ADR-0002 の後継ADR起票（Vercel 不使用・Flutter／Supabase 構成の確定）。
