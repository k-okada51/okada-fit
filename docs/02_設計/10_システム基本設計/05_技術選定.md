| 領域 | 採用技術 | 一言理由 |
|---|---|---|
| 言語 | Dart（アプリ）／TypeScript（Edge Function）／SQL（RPC） | 層ごとに実行環境が違う。1言語への統一はしない（DEC-D01・ADR-0010 で確定） |
| フレームワーク | Flutter（iOS先行・TestFlight配布） | 1コードでiOS/Android。カメラ・通知をネイティブで扱える（DEC-D01・ADR-0010 で確定） |
| UI | Flutter 標準ウィジェット ＋ `fl_chart` | 円形ゲージは `CircularProgressIndicator`、グラフは `fl_chart`（DEC-D05・ADR-0010 で確定） |
| DB | Supabase（PostgreSQL・無料枠） | DB＋認証＋RLS一体（ADR-0004・DEC-B03確定） |
| 実行基盤 | Supabase（Auth／PostgreSQL + RLS／Edge Functions） | **Webホスティングを持たない**。アプリは端末で動く |
| AI | Google Gemini API を Edge Function から直接呼ぶ。既定 `gemini-3.7-flash` | 既定モデルは **ADR-0025 で確定**（価格改定を受け `gemini-3.5-flash` から改訂）。キーを端末に出さない唯一の経路（DEC-B01・ADR-0011 で確定／DEC-D02） |
| 認証 | Supabase Auth | 公開面の本人限定＋RLSで本人行に制限（ADR-0004・DEC-D03確定） |
| 画像 | 食事写真は Edge Function 経由で Gemini へ送信。**永続化しない**（解析後に破棄） | ストレージ不要。送信前に長辺1024pxへ縮小（ADR-0003・DEC-D04確定） |

## 5. 主要な採用理由（横断）
> 📝 ここに層をまたぐ主要な採用理由を記載。{技術選定が満たす要件（NFR/REQ）と設計意図}

- **1アプリ・BaaS集約**: 個人開発（実装者＝岡田さん）で保守負担を最小化。サーバは Edge Function 2本だけ。
- **無料枠中心**: Supabase 無料枠を使う。ホスティング費用は発生しない（配布はTestFlight）。
- **AIはサーバ側**: `GEMINI_API_KEY` を端末に露出させない（境界・DEC-B01・ADR-0011 で確定）。
- **端末は信頼しない**: anon key は公開鍵で、RLS が唯一の遮断機構になる（`02_境界.md §4`・ADR-0005）。
- **決定的処理とAIの分離**: 絞り込み・不足分抽出はDB照会（AI不使用）、生成のみ Gemini API。
- **モデルは設定値**: `GEMINI_MODEL` 環境変数で指定しハードコードしない。精度要件の変化やモデル廃止時は設定変更で対応する。

### 旧構成との対比

| 層 | 旧（ADR-0002 の前提） | 新 |
|---|---|---|
| クライアント | ブラウザ／React + Mantine | iOSアプリ／Flutter + `fl_chart` |
| サーバ | Next.js Route Handlers（`/api/*`） | Supabase Edge Functions（AIを呼ぶ2本のみ） |
| DBアクセス | サーバ経由のみ | 端末から PostgREST・RPC を直接（RLSで保護） |
| ホスティング | Vercel 無料枠 | **持たない**（配布はTestFlight） |
| AI経路 | Vercel AI Gateway（プロバイダ非依存） | Google Gemini API 直接（フォールバックなし） |
