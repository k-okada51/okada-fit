## 3. 連携先ごとの要点
> 📝 ここに連携先ごとの設計要点を記載。{方式／主なIFの役割／認証情報の保管／改変禁止wire等の制約}

### 3.1 Google Gemini API（EXT-01）
- **方式**: Edge Function（Deno）の `fetch` から Gemini API を直接呼ぶ。SDK は使わない。既定モデルは `gemini-3.5-flash`（ADR-0001/DEC-D02）で、環境変数 `GEMINI_MODEL` で指定しハードコードしない。食事写真は `inlineData` の**画像入力**として送る。メニュー提案・タンパク質量は **`responseMimeType`＋`responseSchema` の構造化出力**で受け、zod で検証する。
- **要点**: FEAT-03（メニュー提案）とFEAT-08（写真タンパク質計算）の2用途。呼び出しは **Edge Function からのみ**で、Flutter アプリからは直接呼ばない。部位→器具の絞り込み・不足分の食事抽出はAIを使わない（RULE-004/005）。**ゲートウェイを挟まないため、自動フォールバック先は持たない**（下記 §4）。
- **認証情報**: `GEMINI_API_KEY` は Supabase の Function Secrets に保管。Flutter 側・リポジトリに置かない🔒（NFR-SEC-02）。
- **契約**: Gemini API の外部ワイヤは改変しない。パス・フィールド名の細部は `[仮]` で、実装時に公式ドキュメントで確認する。

#### Gemini API のエラーコード

公式 api-errors ページで確認済み（2026-08-08）。**残高切れは 429 に混ざらず、400 で区別できる。**

| HTTP | error status | 意味 |
|---|---|---|
| 400 | `invalid_request` | リクエストが不正 |
| 400 | `failed_precondition` | 前提条件の未達。**課金が無効な場合を含む** |
| 400 | `parameter_unknown` | 未知のパラメータ |
| 401 | `authentication` | APIキーが無い・不正・失効 |
| 403 | `permission_denied` | キーにこのリソースの権限が無い |
| 404 | `not_found` / `model_not_found` | リソース／モデルが見つからない |
| 429 | `rate_limit_exceeded` | 分/秒あたりの上限超過 |
| 429 | `quota_exceeded` | 日次クォータの超過 |
| 500 | `api_error` | サーバ側の想定外エラー |
| 503 | `service_unavailable` | 一時的な過負荷・停止 |
| 504 | `deadline_exceeded` | 期限内に完了しなかった |

#### ERRマッピング

| 事象 | Gemini の応答 | error_code | HTTP | retryable |
|---|---|---|---|---|
| レート制限（分/秒） | 429 `rate_limit_exceeded` | `ERR-AI-RATE` | 429 | true（指数バックオフ） |
| 日次クォータ超過 | 429 `quota_exceeded` | `ERR-AI-QUOTA`（新設） | 429 | false（当日は再送しても通らない） |
| 課金無効・請求未設定 | 400 `failed_precondition` | `ERR-AI-CREDIT` | 402 | false |
| キー無効・権限なし | 401 `authentication` / 403 `permission_denied` | `ERR-AI-FAIL` | 500 | false |
| モデル不明 | 404 `model_not_found` | `ERR-AI-FAIL` | 500 | false |
| サーバ障害 | 500 `api_error` / 503 `service_unavailable` | `ERR-AI-FAIL` | 500 | false |
| タイムアウト | 504 `deadline_exceeded` | `ERR-AI-TIMEOUT` | 504 | false |
| 構造化出力が型不一致 | 200 だが検証失敗 | `ERR-AI-SCHEMA`（新設） | 502 | false |

新設するERRは2つ。分ける理由は次のとおり。

| ERR | 理由 |
|---|---|
| `ERR-AI-QUOTA` | 429 だが**再送しても当日は通らない**。`ERR-AI-RATE` と同じ扱いにすると無駄な再送を続ける |
| `ERR-AI-SCHEMA` | 呼び出し自体は成功している。`ERR-AI-FAIL` に混ぜると原因を切り分けられない |

- 縮退はいずれも同じ。**AI機能だけ止め、記録と閲覧は続ける**（NFR-AVAIL-05）。
- 契約の正本は `30_データ・IF設計/02_API設計.md §5`、実装ワイヤは `50_詳細設計/03_外部連携IF/10_GeminiAPI連携.md`。
