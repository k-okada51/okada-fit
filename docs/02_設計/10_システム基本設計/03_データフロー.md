# データフロー（DFD） — {システム名}

> **目的**: システムの**静的な地図**（データがどこから来て・どう変換され・どこへ出るか）を Level0（コンテキスト）／Level1（主要プロセス）で示す。時系列の動きは扱わない。
> **書き方**:（記入例は example-suido-fax の対応ファイル参照）作図方針・記法凡例・チェックリストは本ファイル内に記載。**ビジネス（人・意思決定・成果）を第一級で含める**（利用者・承認者・経営などのアクターと業務上の意思決定/成果フロー）。時系列の動きはDFDでなくシーケンス図／`03_ドメインイベント.md` で。

| 要素 | 意味 | Mermaid形状（例） |
|---|---|---|
| 外部エンティティ | システム外の相手（人・組織・外部システム） | `([人/組織])` `[[外部システム]]` |

## 2. レベル0：コンテキストDFD
> 📝 ここにシステムを1プロセスに置いた全体像をMermaidで記載。**ビジネスの入出力**（利用者の入力・承認、経営の方針・KPI、成果レポート）を必ず含める。ラベルは業務データの意味で書く。%% ここに記載

```mermaid
flowchart LR
  classDef biz fill:#e6f0ff,stroke:#2b5cff;
  classDef ext fill:#eef1f4,stroke:#98a2b3;
  classDef proc fill:#def,stroke:#06c,stroke-width:2px;

  USER([利用者/オペレーター]):::biz
  APPROVER([承認者/管理者]):::biz
  MGMT([経営/意思決定者]):::biz
  EXTSYS[[外部システム（連携先）]]:::ext

  P0((( システム名 ))):::proc

  %% ここに記載（アクターとの主要データフローを追記）
  USER -->|入力・操作| P0
  P0 -->|状態・結果| USER
  APPROVER -->|承認・設定| P0
  MGMT -->|方針・KPI| P0
  P0 -->|成果・監査レポート| MGMT
  P0 -->|連携データ| EXTSYS
  EXTSYS -->|応答データ| P0
```

## 3. レベル1：主要プロセス＋データストア
> 📝 ここにレベル0の1プロセスを主要プロセス（P1〜Pn）とデータストア（D1〜Dn）に分解して記載。プロセス間・ストアとのフローに業務データを明記。見づらければ主要な相手ごとに複数枚に分割する。%% ここに記載

```mermaid
flowchart TB
  classDef biz fill:#e6f0ff,stroke:#2b5cff;
  classDef ext fill:#eef1f4,stroke:#98a2b3;
  classDef proc fill:#def,stroke:#06c;
  classDef ds fill:#ffd,stroke:#a80;

  USER([利用者]):::biz
  APPROVER([承認者]):::biz
  EXTSYS[[外部システム（連携先）]]:::ext

  P1((P1 受付・入力検証)):::proc
  P2((P2 中核処理)):::proc
  P3((P3 外部連携)):::proc
  P4((P4 承認・確定)):::proc

  D1[(D1 マスタ)]:::ds
  D2[(D2 トランザクション/ログ)]:::ds

  %% ここに記載（プロセス間・ストアとのフローと業務データを追記）
  USER --> P1 --> P2
  P2 --> D1
  P2 --> P3
  P3 <-->|連携データ| EXTSYS
  P3 --> P4
  P4 <-->|承認・修正| APPROVER
  P4 --> D2
```
