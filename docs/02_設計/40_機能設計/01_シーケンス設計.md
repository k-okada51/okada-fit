## 1. FEAT-08 食事撮影・タンパク質計算
対応画面: SCR-04 食事記録 ／ API: `POST /api/meals/analyze`・`POST /api/meals`（EXT-01）／ 写真は非保存（ADR-0003）

```mermaid
sequenceDiagram
  actor U as 岡田さん
  participant B as ブラウザ(Mantine)
  participant S as Route Handler
  participant G as AI Gateway→Gemini
  participant D as DB(Supabase)

  U->>B: 📷 撮影（input capture）
  B->>B: プレビュー＋長辺1024pxにリサイズ
  Note over B: この時点では未送信（自動送信しない）
  U->>B: [解析する]
  B->>S: POST /api/meals/analyze（画像）
  S->>S: Supabase Authで本人確認
  S->>G: generateObject（画像＋schema, gemini-3.5-flash）
  alt 成功
    G-->>S: {food_name, dish_names[], kcal, protein, sugar, fat}
    S-->>B: 栄養4項目を返す（画像は破棄）
    B->>U: 📊 栄養価を表示＋[記録する]
    U->>B: [記録する]
    B->>S: POST /api/meals（栄養4項目）
    S->>D: meal_logs へ保存（画像カラムなし）
    S-->>B: 保存OK
    B->>U: 「記録しました」トースト＋残量再計算
  else AI失敗（402/429/timeout）
    G-->>S: エラー
    S-->>B: ERR-AI-*（§API設計§5）
    B->>U: 「解析に失敗しました」トースト（記録・閲覧は継続・NFR-AVAIL-05）
  end
```

- ローディング表示は最大20秒想定（NFR-PERF-04）。非冪等・自動リトライなし。
- 撮影→プレビュー→[解析する]→[記録する] の2ステップで、失敗写真の無駄な課金を防ぐ。

## 2. FEAT-03 AIメニュー提案
対応画面: SCR-03 トレーニング ／ API: `GET /api/machines?body_part=`・`POST /api/menus/generate`（EXT-01）

```mermaid
sequenceDiagram
  actor U as 岡田さん
  participant B as ブラウザ
  participant S as Route Handler
  participant G as AI Gateway
  participant D as DB

  U->>B: 部位を選択（胸/背中/脚/肩/腕）
  B->>S: GET /api/machines?body_part=胸
  S->>D: 部位→種目(training_menus)→中間(machine_menus)→器具(training_machines) を DISTINCT 照会（AI不使用・RULE-004）
  D-->>S: 器具リスト（重複排除済み）
  S-->>B: 器具リスト
  B->>U: 器具を表示
  U->>B: [メニュー生成]
  B->>S: POST /api/menus/generate（body_part, machine_ids）
  S->>G: generateObject（提案メニュー）
  G-->>S: {menus:[{name, how_to}]}
  S-->>B: 提案メニュー
  B->>U: メニュー表示（記録へ）
```

- 器具↔種目は多対多（中間テーブル `machine_menus`）。1台の器具が複数部位に対応する。
- 生成前の検証は「器具が指定部位の種目を1つ以上持つ」で判定する（部位の完全一致ではない）。

## 3. FEAT-05 ダッシュボード表示
対応画面: SCR-01 ダッシュボード ／ API: `GET /api/dashboard?period=month`

```mermaid
sequenceDiagram
  actor U as 岡田さん
  participant B as ブラウザ(Mantine)
  participant S as Route Handler
  participant D as DB

  U->>B: ダッシュボードを開く
  B->>S: GET /api/dashboard?period=month
  S->>D: 当日摂取(meal_logs SUM)・目標(体重×2g)・実施日(training_sessions/details)を集計
  D-->>S: 集計結果
  S-->>B: {protein_gauge, heatmap}
  B->>U: RingProgress(達成率100%頭打ち)＋Heatmap(実施有無・種目名ツールチップ)
  U->>B: 期間切替(SegmentedControl 日/週/月)
  B->>S: GET /api/dashboard?period=week
  Note over B,S: 表示範囲を差し替え（保持制限なし＝全履歴）
```

- 初期表示 ≤2秒（NFR-PERF-01）。チャートは `next/dynamic` で遅延ロード。

## 4. FEAT-02 部位→器具の絞り込み
対応画面: SCR-02 器具登録／SCR-03 ／ API: `GET /api/machines?body_part=`（AI不使用の決定的処理・RULE-004）

```mermaid
sequenceDiagram
  actor U as 岡田さん
  participant B as ブラウザ
  participant S as Route Handler
  participant D as DB
  U->>B: 部位を選択
  B->>S: GET /api/machines?body_part=脚
  S->>D: training_menus(body_part=脚) → machine_menus → training_machines を DISTINCT で JOIN 照会
  D-->>S: 該当器具（重複排除済み）
  S-->>B: 器具リスト（≤1秒・NFR-PERF-02）
  B->>U: 絞り込み結果を表示
```

- 器具↔種目は多対多。中間テーブル `machine_menus` を必ず経由する。
- **`DISTINCT` が必須**。1台が同じ部位の種目を複数持つと、付けないと同じ器具が重複して返る。

## 5. FEAT-09 タンパク質残量・不足分提示
対応画面: SCR-01／SCR-04 ／ API: `GET /api/protein/remaining`（AI不使用・DB照会）

```mermaid
sequenceDiagram
  actor U as 岡田さん
  participant B as ブラウザ
  participant S as Route Handler
  participant D as DB
  B->>S: GET /api/protein/remaining
  S->>D: 目標(体重×2g)−当日摂取(meal_logs SUM)＝残量、foodsから不足を補う候補を照会
  D-->>S: {target, intake, remaining, suggestions}
  S-->>B: 残量＋補う食品候補（RULE-005・AI不使用）
  B->>U: 「あと○g・△△を食べると補える」
```
