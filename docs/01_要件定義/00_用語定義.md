## 3. ID付番規則
> 📝 ここにID接頭辞と付番ルールを記載。IDは**不変・欠番再利用禁止**。本記法は共通ハーネス(aic-harness)の要件レビュー(criteria.json)に準拠。

- **ハーネスID接頭辞（aic-harness/criteria.json 準拠）**: `FEAT-`（機能）/`ST-`（状態）/`TR-`（状態遷移）/`ERR-`（エラー）/`SCR-`（画面）/`RPT-`（帳票）/`EXT-`（外部連携）/`RULE-`（業務ルール）/`TASK-`（タスク）。
- **受入基準**＝`- [AC] Given <前提> When <操作> Then <期待>`（各 FEAT- にぶら下げる＝TDDのRED源泉・collect.py の測定対象）。
- **未記入マーカー**＝`<!-- TODO:aic -->`（記入待ちの空欄に置く）。
- **未決事項**＝各件に「オーナー」「解決フェーズ(設計/実装/運用)」を持たせる（`01_要件定義/01_全体像/05_未決定事項.md`）。
- **文書ステータス（システム的に管理）**＝**「mainにマージ済み＝承認済み」**（mainのブランチ保護＝PR＋メンバー承認 で担保。承認印は手書きしない）。先頭 frontmatter の `status:` は**「未完成のまま載せる」例外宣言だけ**に使う（`draft`＝書きかけ／`ai-reviewed`＝AI独立レビュー済／`wip`）。**status宣言が無い（＝承認相当）文書に `📝`／`{…}`／`<!-- TODO:aic -->`／`[仮]`／`🔧DESIGN` が残っていてはならない**（CIが検出・次工程AIが未確定値を実装に使う事故を防ぐ）。承認履歴（誰が/いつ）は **PR/git が正**（in-doc手書き不要）。
- **設計側の独自ID（harness観点外）**: `NFR-/DM-/DEC-/TC-/REQ-/KPI-`（我々の設計層で用いる補助ID。ハーネスの要件レビュー対象外）。
- IDは**不変・欠番再利用禁止**。

> 命名規約（物理命名：DB/enum/API/JSON/エラーコード/サービス）は `../02_設計/50_詳細設計/06_DB設計規約.md` を正（将来は共通ハーネス運用へ）。
