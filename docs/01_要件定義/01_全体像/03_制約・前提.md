## 1. In-Scope
> 📝 ここに対象範囲（やること）を記載。含める項目: 本PJで新規に作る/対応する機能・資産を箇条書きで。

- ジムの器具登録（器具マスタ）と、各器具への部位（筋肉）タグ付与
- 部位タグによる器具の絞り込み（鍛えたい部位で使える器具を提示）
- ボタン押下によるAIメニュー提案（登録器具から、選択した部位のトレーニングメニューを提案）
- トレーニング記録（実施した回数・重量・メニュー）
- ダッシュボード／可視化（履歴・前回実施）
- 体重入力と、体重×2gによる1日の必要タンパク質量の自動算出
- 食事撮影とAIによるタンパク質量の計算
- 必要量に対する残量（必要量−摂取量）の表示
- 残量を補う食事の提示（食事マスタから決定的に抽出）
- 食事マスタのCSVインポート（初期取り込み）
- 初期設定（目標ログイン回数・体重の設定 ほか）
- 提供形態は Webアプリ（ブラウザ）

## 2. Out-of-Scope
> 📝 ここに対象外（やらないこと）を記載。含める項目: やらない要件／その理由／再検討時期（Phase2・別案件など）。

| やらない要件 | 理由 | 再検討時期 |
|---|---|---|
| 目標体型（ダイエット/減量/増量）の選択と、それに基づく食事メニュー生成 | 要件がないため（栄養はタンパク質トラッキングのみIn-Scope） | 対象外 |
| 多人数／他ユーザ展開・マルチテナント・アカウント管理 | 岡田さん個人利用で確定 | Phase2以降（プロダクト化を検討する場合） |
| 3日ルール・回復日数を用いたローテーション提案 | メニュー提案はボタン押下で選択部位に対して行うため不要 | Phase2以降（必要になれば） |
| システムからの自動/定期のメニュー提案（プッシュ） | 提案はボタン押下のオンデマンドで行うため不要 | Phase2以降（必要になれば） |

> ⚠️ 要確認（人間判断）: 上記以外の Out-of-Scope（例: SNS共有・他者比較・ウェアラブル連携など）は議事で言及なし。追加の対象外要件があれば追記する。

## 3. 技術・アーキ制約
> 📝 ここに技術・アーキ上の制約を記載。含める項目: 採用/不採用の技術方式、同時実行や経路の制約、改変禁止のインタフェース等と、その根拠ID。

| 制約 | 内容 | 根拠 |
|---|---|---|
| 提供形態 | Webアプリ（ブラウザ）とする | 議事決定（DEC-B02） |
| データ保存 | サーバ側の無料枠のDBに保存する（具体プロダクトは実装時に選定） | 議事決定（DEC-B03） |
| 単一ユーザ前提 | 認証・マルチテナントを持たない設計でよい `[仮]` | 個人利用で確定 |
| AI利用箇所 | メニュー提案（ボタン押下）と食事写真のタンパク質計算の2箇所に Claude（画像入力対応）を用いる | 議事決定（DEC-B01） |
| 決定的処理（AI不使用） | 部位→器具の絞り込み、不足分の食事提示（食事マスタからの抽出）はAI不使用 | 議事決定 |
| 部位タグ体系 | 部位タグは 胸・背中・脚・肩・腕 の5部位 | 議事決定（DEC-B04） |
| ローテーション不使用 | 3日ルール・回復日数・自動提案は実装しない | 議事決定 |
| 技術スタック | ⚠️ 要確認: 言語・フレームワーク未定 | — |
