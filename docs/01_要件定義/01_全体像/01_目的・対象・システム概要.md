## 1. 目的
### 1.1 ビジネス目的
> 📝 ここに主目的を記載。含める項目: 発注元は誰か／対象業務は何か／As-Isの手作業や課題／To-Beで何に置き換えるか（1文で要約）。

発注元 兼 唯一の利用者は岡田さん（個人）。対象業務は岡田さん自身の筋トレ（トレーニングメニューの決定・実施記録）とタンパク質摂取の管理。As-Isでは器具と部位の対応・やるメニューを記憶や手動メモで管理して**毎回同じメニューになりがち**で、タンパク質摂取量も把握できていない。To-Beでは、器具に付与した部位タグで使える器具を絞り込み、鍛えたい部位を選んでボタンを押すと登録器具からAIがその部位のトレーニングメニューを提案し（毎回同じメニューになるのを防ぐ）、実施記録（回数・重量・メニュー）・可視化を1つのWebアプリで行う。あわせて、体重×2gで算出した1日の必要タンパク質量に対し、食事を撮影するとAIがタンパク質量を計算して残量を示し、不足分を補う食事を食事マスタから提示する。これらにより、**岡田さんの筋トレを快適にする**（＝ジムで鍛える以外の余計なことを考えずに済む状態にする）。

## 3. システム概要
> **書き方**: 散文の説明より、構成表・資産表で「責務」を明確に。用語はglossaryと揃える。

### 3.1 全体像
> 📝 ここにシステム全体像を記載。含める項目: システム名／起点となる操作やイベント／入力から出力までの一連の流れを1〜2文で。

システム名は okada-fit（仮称）、提供形態はWebアプリ（ブラウザ）。トレーニングは、器具登録（部位タグ付与）を起点に、鍛えたい部位を選び、部位タグで使える器具を絞り込み、generateボタン押下で登録器具からAIが「選択した部位のトレーニングメニュー」を提案、実施結果（回数・重量・メニュー）を記録してダッシュボードで可視化する。栄養は、体重から1日の必要タンパク質量を算出し、食事を撮影するとAIがタンパク質量を計算して残量（必要量−摂取量）を示し、不足分を補う食事を食事マスタ（CSVで初期取り込み）から抽出して提示する。

### 3.2 主要構成
> 📝 ここに主要な構成要素を記載。含める項目: サービス/モジュール名（表示名・内部名）と各々の責務を一言で。

| 構成要素 | 内部名 | 責務 |
|---|---|---|
| 器具マスタ登録 | equipment-registry `[仮]` | ジムにある器具を登録し、各器具に部位（筋肉）タグを付与・管理する |
| 部位→器具の絞り込み | muscle-equipment-filter `[仮]` | 器具の部位タグをもとに、鍛えたい部位で使える器具を絞り込み・提示する（決定的処理、AI不使用） |
| メニュー生成（AI） | menu-generator `[仮]` | generateボタン押下で、登録済み器具（部位タグ付き）から選択した部位のトレーニングメニューをAIが提案する |
| トレーニング記録 | workout-log `[仮]` | 実施した回数・重量・メニューを記録する |
| ダッシュボード／可視化 | dashboard `[仮]` | 履歴・前回実施を可視化しモチベーションを支える |
| 必要タンパク質量の算出 | protein-target `[仮]` | 体重×2gで1日の必要タンパク質量を算出する |
| 食事撮影・タンパク質計算（AI） | protein-estimator `[仮]` | 食事写真からAIがタンパク質量を計算する |
| タンパク質残量・不足分提示 | protein-tracker `[仮]` | 必要量−摂取量の残量を表示し、食事マスタから不足分を補う食事を抽出・提示する（AIなし） |
| 食事マスタ（CSVインポート） | food-master `[仮]` | 食品ごとのタンパク質量等をCSVで初期取り込みし管理する |
| 初期設定 | onboarding `[仮]` | 目標ログイン回数・体重などの初期設定を行う |

> ⚠️ 要確認（人間判断）: 内部名は暫定 `[仮]`。モジュール分割・命名は基本設計で確定する。

### 3.4 採用構成の要点
> 📝 ここに採用構成のポイントを記載。含める項目: 設計上の重要な決めごと（分離境界・唯一の経路・依存排除など）を箇条書き。詳細な案比較は `02_課題・解決・業務フロー.md` の解決方法へ委譲。

- 提供形態は **Webアプリ（ブラウザ）** とする（DEC-B02）。
- **単一ユーザ（岡田さん専用）前提**。認証・マルチテナントは持たない設計でよい `[仮]`（個人利用で確定）。
- トレーニングのコアループは「**部位選択（部位タグで器具を絞り込み）→ generateボタンでAIがその部位のメニューを提案 → 実施 → 記録 → 可視化**」の一本道とする。
- 栄養は「**体重×2gで必要タンパク質量を算出 → 食事撮影でAIがタンパク質計算 → 残量表示 → 食事マスタから不足分を提示**」。
- **AIはメニュー提案（ボタン押下）と食事写真のタンパク質計算の2箇所**に用いる。採用サービスは **Claude（画像入力対応）**（DEC-B01）。部位→器具の絞り込みと不足分の食事提示（食事マスタからの抽出）は**決定的処理（AI不使用）**とする。
- 部位タグは **胸・背中・脚・肩・腕** の5部位（DEC-B04）。必要タンパク質量は **体重×2g** で自動算出する（DEC-B06）。食事マスタは**CSVで初期取り込み**する（スキーマはDEC-B05）。
- データは**サーバ側のDB**に保存する（**無料枠のDBを採用**、具体プロダクトは実装時に選定＝DEC-B03）。
- **3日ルール・回復日数・自動/定期のローテーション提案は行わない**（生成はボタン押下のオンデマンド）。
- **目標体型（ダイエット/減量/増量）に基づく食事メニュー生成は対象外**（栄養はタンパク質トラッキングのみ。[`03_制約・前提.md`](03_制約・前提.md) §2）。
- メモアプリでも代替可能な機能だが、**継続率（モチベーション）を高めるUI／サマリー表示**を重視する。
- 手段の案比較の詳細は [`02_課題・解決・業務フロー.md`](02_課題・解決・業務フロー.md) §3 へ委譲。
