# ADR-0020: 無料枠のプロジェクト停止を許容する

> **目的**: 1つの設計決定を記録する雛形（1決定＝1ファイル）。本ファイルをコピーし `NNNN-短い決定名.md`（NNNN＝DEC番号のゼロ埋め）で起票する。

## 背景・課題（Context）
> 📝 ここに何を・なぜ決める必要があるかを記載。関連する要件ID（FEAT/NFR/DM/IF/ST/ERR）を明記する。{決定が必要な理由／制約／前提}

- **対象要件**: NFR-AVAIL-01（稼働率）・NFR-AVAIL-03（RTO）。
- 2026-08-08 に Supabase 公式ドキュメントで確認した。**無料枠は1週間の無操作でプロジェクトが一時停止する。**

| 項目 | 確認した内容 |
|---|---|
| 判定 | 「過去1週間に十分な**利用者DBアクティビティ**が無い」場合に停止する |
| しきい値 | **公開されていない。** 「十分な」としか記載が無い |
| 対象プラン | **無料枠のみ。** 有料プランは停止されない |
| データ | **失われない** |
| 復帰 | ダッシュボードから可能。**猶予は1年** |

- **本PJは現実に該当しうる。** 利用者は岡田さん1人で、ジムに行かない週があれば操作が途切れる。
- 一方、**一般の公開サービスはこの条件に当たらない。** 利用者がいれば毎日クエリが走る。制限を回避しているのではなく、そもそも条件に該当しない。

## 選択肢（Options / Alternatives）
> 📝 ここに検討した案を記載（採用案・却下案の両方）。{案／概要／長所／短所}

| 案 | 概要 | 長所 | 短所 |
|---|---|---|---|
| **A（採用）** | **許容する。** 停止したらダッシュボードから復帰する | 追加実装ゼロ・追加費用ゼロ。**データは失われない** | 気づくまでアプリが動かない |
| B | 日次エクスポートの直後に軽い SELECT を投げて確実に防ぐ | 実装は数行 | **しきい値が非公開のため、これでも保証にならない**。効果を検証できない |
| C | 有料プランに上げる | 停止しない。バックアップ・ログ保持も同時に解決する | 月額費用が発生する。ADR-0016／0017／0019 の前提をまとめて見直すことになる |

## 決定（Decision）
> 📝 ここに採用案と、具体値・方式を実装が迷わない粒度で記載。{採用案／確定した具体値・方式}

案 **A** を採用する。**停止を許容する。**

| 項目 | 値 |
|---|---|
| 停止の扱い | **許容する。** 障害として扱わない |
| 復帰手段 | Supabase ダッシュボードから手動で再開する |
| 復帰の猶予 | 1年 |
| データ | 失われない |
| 停止防止の実装 | **持たない**（案B は採らない） |
| 有料プラン | 上げない |

- **アプリ側に停止検知・復帰導線を実装しない。** 停止中は通信エラーとして扱われる。
- 利用者＝運用者であるため、「アプリが動かない → ダッシュボードを見る」が成立する。

### 日次エクスポートが実質の予防になる見込み

**ADR-0017 の日次エクスポートは毎日 DB へ接続してクエリを発行する。** これが停止の予防になる可能性が高い。

| 項目 | 内容 |
|---|---|
| 期待 | 毎日DBアクティビティが発生し、無操作の判定に至らない |
| **保証の有無** | **無い。** しきい値が非公開で、`pg_dump` が「利用者アクティビティ」に数えられるかも不明 |
| Mac が落ちている場合 | エクスポートも走らない。予防も効かない |

- **これは設計上の期待であって前提ではない。** 効かなくても案Aの結論は変わらない。

## 根拠（Rationale）
> 📝 ここになぜその案かを記載。トレードオフ・却下理由を明示する。{選定理由／却下した案の理由}

- **データが失われない。** これが決定的である。停止は可用性の問題であって、データ保全の問題ではない。
- **利用者と運用者が同一人物である。** 「アプリが動かない」ことに本人が即座に気づき、本人が復帰できる。第三者への影響が無い。
- **案Bは効果を検証できない。** しきい値が非公開である以上、実装しても「効いているか」を確かめる手段が無い。検証できない対策は保守の負債になる（NFR-MAINT-01）。
- **案Cは費用に見合わない。** 停止しても実害が「復帰操作1回」であるため、月額を払う理由にならない。

**却下理由**

| 案 | 却下理由 |
|---|---|
| B | しきい値が非公開で保証にならない。検証できない対策は持たない |
| C | 実害が復帰操作1回に留まる。月額費用に見合わない |

## 影響（Consequences）
> 📝 ここに決定がもたらす影響を記載。{反映先ドキュメントの該当箇所／関連テスト観点／前提が崩れた場合の再検討条件}

- **NFR-AVAIL-01（稼働率）を厳密には満たさない。** 停止した週の稼働率は0%になる。
  - ただし原因は障害ではなく**無料枠の仕様**であり、復帰は手動操作1回である。
  - ⚠️ 要確認（人間判断）: **NFR-AVAIL-01 の稼働率に、無料枠の停止を除外条件として書くか**（🟢 低・要件ブランチへの申し送り）。
- **NFR-AVAIL-03（RTO 数時間）は復帰操作の速さに依存する。** 気づかなければ数日になりうる。実害はデータではなく利用機会の損失に限られる。
- **開発面の影響がある。** dev プロジェクトが停止していると `04_移行設計.md §3` のリハーサルを始められない。§4 の時間割に「停止していないかの事前確認」を置く（同書 §6.2 #10）。
- 反映先:
  - `02_設計/20_インフラ設計/01_システム構成・環境.md §2`（⚠️ の解決）
  - `02_設計/20_インフラ設計/02_IaC・デプロイ・可用性配置.md §3`（⚠️ の解決）
  - `02_設計/50_詳細設計/04_移行設計.md §6.2 #10`（開発面の影響は残る）
