## 背景・課題（Context）
> 📝 ここに何を・なぜ決める必要があるかを記載。関連する要件ID（FEAT/NFR/DM/IF/ST/ERR）を明記する。{決定が必要な理由／制約／前提}

- **対象要件**: FEAT-03（AIメニュー提案）・FEAT-08（食事撮影タンパク質計算）。連携は EXT-01。
- 2026-08-08 に Gemini API の公式ドキュメントを確認し、**設計の記述が誤っていた**ことが判明した。

| 項目 | 旧稿 | 正しくは |
|---|---|---|
| パラメータ名 | `generationConfig.thinkingConfig` | **`thinking_level`** |
| 値 | `high` | `minimal` / `low` / **`medium`（既定）** / `high` |
| 併用 | — | `thinking_budget`（旧）と併用すると **400 エラー** |

- **`high` を選んだ根拠が失われていた。** 経緯は次のとおり。

| # | 経緯 |
|---|---|
| 1 | ADR-0001 が PoC 実測（`reasoning: high`）を根拠に `high` を選んだ |
| 2 | 指定は `providerOptions.google.thinkingConfig`。**AI SDK 経由の旧パラメータ体系**だった |
| 3 | ADR-0011 が経路を Gemini API 直接に改訂したが、**思考量には触れなかった** |
| 4 | ADR-0001 は Superseded。結果として **`high` を定める現行の記録が無い**状態だった |

- さらに新体系では **`medium` が既定**になった。`high` は既定より上を明示的に選ぶ指定になる。

> 📝 ここに検討した案を記載（採用案・却下案の両方）。{案／概要／長所／短所}

| 案 | 概要 | 長所 | 短所 |
|---|---|---|---|
| **A（採用）** | **`thinking_level: medium`（既定）** | 応答が速くなる見込み。出力トークンが減りコストが下がる見込み。**既定であり公式の推奨** | 精度が落ちる可能性がある。実測していない |
| B | `thinking_level: high` を維持 | ADR-0001 の実測条件に近い | **根拠が失われている**。旧パラメータ体系の測定であり、そのまま引き継げない。遅く高い |
| C | 実測してから決める | 根拠を持って決められる | 実装前に測れない。**設計を止める理由にならない**（既定値で始めれば足りる） |

## 決定（Decision）
> 📝 ここに採用案と、具体値・方式を実装が迷わない粒度で記載。{採用案／確定した具体値・方式}

案 **A** を採用する。**`thinking_level: medium` とする。**

| 項目 | 値 |
|---|---|
| パラメータ | `thinking_level` |
| 値 | **`medium`** |
| 適用範囲 | FEAT-03（`generate-menu`）・FEAT-08（`analyze-meal`）の両方 |
| 併用禁止 | `thinking_budget`（旧）は使わない。併用すると 400 エラーになる |

- **`high` は使わない。**
- 値は環境変数化しない。定数として `_gemini.ts` に置く。変更時はコード変更＋デプロイとする。
- 理由は、切替の頻度が低く、環境変数を増やすほうが保守を増やすため（NFR-MAINT-01）。

## 根拠（Rationale）
> 📝 ここになぜその案かを記載。トレードオフ・却下理由を明示する。{選定理由／却下した案の理由}

- **`high` を選び直す根拠が無い。** ADR-0001 の実測は旧パラメータ体系のもので、そのまま新体系の `high` を正当化しない。
- **既定に従うのが妥当である。** 公式が `medium` を「ほとんどのタスクに推奨」としている。根拠が無い状態で既定を外れる理由が無い。
- **精度が足りなければ上げればよい。** `medium` → `high` は1行の変更で、後戻りのコストが小さい。
- 逆に `high` で始めると、下げてよいかを判断する機会が来ない。**速くも安くもならないまま固定される。**

**却下理由**

| 案 | 却下理由 |
|---|---|
| B | 根拠の無い `high` を引き継ぐことになる。遅く高い側に倒れる |
| C | 実装前に実測できない。既定値で始めれば設計は止まらない |

## 影響（Consequences）
> 📝 ここに決定がもたらす影響を記載。{反映先ドキュメントの該当箇所／関連テスト観点／前提が崩れた場合の再検討条件}

- **NFR-PERF-03/04（AI応答の所要時間）に効く。** `medium` のほうが速い見込みだが、**実測していない。**
- **コストにも効く。** 出力トークンは推論が支配的なため、思考量を下げると単価が下がる見込み。
- ⚠️ 要確認（人間判断）: **精度が `medium` で足りるかは未実測（🟡 中）。**
  - ADR-0001 の実測値（外食 総合MAPE 14.7%・応答6.3秒）は `high` かつ旧体系のもの。**`medium` の数値は持っていない。**
  - 特に FEAT-08 の脂質は `high` でも MAPE 32.7% と弱い。ここが `medium` でさらに落ちる可能性がある。
  - **実装後に FEAT-08 の精度を確認し、許容外なら `high` へ上げる。**
