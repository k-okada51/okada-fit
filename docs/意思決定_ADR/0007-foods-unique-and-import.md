## 背景・課題（Context）
> 📝 ここに何を・なぜ決める必要があるかを記載。関連する要件ID（FEAT/NFR/DM/IF/ST/ERR）を明記する。{決定が必要な理由／制約／前提}

- **対象要件**: FEAT-10（食事マスタCSVインポート）・FEAT-09（不足分提示）・NFR-MIGR-02（初期データ投入）。
- `foods.name`（DM-09）に UNIQUE が無い。同じCSVを2回流すと重複が積み上がる。
- 現行の RPC は `replace_foods(jsonb)`。DELETE → 一括INSERT の全置換である。
- **全置換は取込中に候補が空になる。** FEAT-09 の不足分提示が一時的に何も返さない。
- 取込が途中で失敗すると、それまでのマスタごと失う。
- **1件だけ追加する手段が無い**（FEAT-10 #12）。CSVを作り直す必要があった。
- `foods` に `user_id` が無く、所有の扱いが未決だった（FEAT-10 #1・FEAT-09 #3）。
- **前提**: `foods` は数百件想定。CSV は Excel 由来で表記が揺れる。

## 選択肢（Options / Alternatives）
> 📝 ここに検討した案を記載（採用案・却下案の両方）。{案／概要／長所／短所}

| 案 | 概要 | 長所 | 短所 |
|---|---|---|---|
| 全置換（現行） | DELETE → 一括INSERT | 冪等。実装が単純 | 取込中に候補が空になる。1件追加ができない |
| **UNIQUE＋追加＋スキップ（採用）** | `INSERT … ON CONFLICT (name) DO NOTHING` | 冪等。既存行を消さない。1件追加にも同じ経路が使える | 既存行の値を直せない。訂正は別手段が要る |
| UNIQUE＋upsert | `INSERT … ON CONFLICT (name) DO UPDATE` | 値の修正ができる | 古いCSVの再取込が正しい値を書き戻す。意図しない上書きが起きる |

## 決定（Decision）
> 📝 ここに採用案と、具体値・方式を実装が迷わない粒度で記載。{採用案／確定した具体値・方式}

`foods.name` に UNIQUE を張り、**追加＋重複スキップ**で取り込む。

### 所有

- `foods` は**共通マスタ**。所有者列（`user_id`）を持たない。
- RLS は共通マスタ区分に従う（ADR-0005）。認証済みなら参照できる。

### 一意制約

```sql
CREATE UNIQUE INDEX uq_foods_name ON foods(name);
```

- **INDEX は7本になる**（既存6本＋`uq_foods_name`）。テーブル数は10本のまま。

### 正規化（案i: 正規化後の文字列を保存する）

Flutter 側で正規化してから送る。**保存されるのも正規化後の文字列。**

| 処理 | 例 |
|---|---|
| 前後の空白を除去 | `　鶏むね肉 ` → `鶏むね肉` |
| 全角英数字を半角へ | `ＭＣＴオイル` → `MCTオイル` |
| 英字を小文字へ | `Whey` → `whey` |
| 連続する空白を1つへ | `鶏  むね肉` → `鶏 むね肉` |

- **カタカナの表記ゆれは吸収しない。** 別物を同一視する事故を避けるため。

### 取込方式

**全置換をやめる。追加＋重複スキップにする。**

| 項目 | 旧 | 新 |
|---|---|---|
| RPC名 | `replace_foods(jsonb)` | **`import_foods(jsonb)`** |
| 方式 | DELETE → 一括INSERT | `INSERT … ON CONFLICT (name) DO NOTHING` |
| 戻り値 | `deleted_count` / `inserted_count` | **`inserted_count` / `skipped_count`** |
| 既存と同名で値が違う行 | — | **スキップする。上書きしない** |
| 冪等性 | 全置換なので冪等 | **同じCSVを2回流しても結果は同じ** |

- 画面には「取込 N件・スキップ M件」を出す。
- 1件だけ追加する用途にも同じ経路を使う（#12 の解決）。
- 引数名は `p_rows`、関数名は snake_case（`06_DB設計規約.md §5`）。

## 根拠（Rationale）
> 📝 ここになぜその案かを記載。トレードオフ・却下理由を明示する。{選定理由／却下した案の理由}

**採用理由**

- 同じCSVを2回流しても結果が変わらない。NFR-MIGR-02 の冪等性を満たす。
- 既存行を消さないため、取込中に候補が空になる時間が生じない。
- 1件追加とCSV一括取込を同じ経路で扱える。実装が1本で済む。
- 正規化後の文字列を保存すると、比較キーと保存値が一致する。式INDEXが要らない。

**却下理由**

| 案 | 却下理由 |
|---|---|
| 全置換 | 取込中に `foods` が空になる。FEAT-09 の候補提示が落ちる |
| 全置換 | 失敗するとマスタごと失う。復旧に正しいCSVが要る |
| upsert | 古いCSVの再取込が、直した値を元に戻す。事故が静かに起きる |

- 保存値が入力と変わる点は許容する。食品名の空白・全角半角は意味を変えない。
