## 背景・課題（Context）
> 📝 ここに何を・なぜ決める必要があるかを記載。関連する要件ID（FEAT/NFR/DM/IF/ST/ERR）を明記する。{決定が必要な理由／制約／前提}

- **対象要件**: FEAT-08（食事撮影タンパク質計算）・FEAT-03（AIメニュー提案）。いずれも LLM を利用し、FEAT-08 は画像入力（vision）＋構造化出力を必須とする。連携は EXT-01。
- **当初想定**: DEC-B01 で「AI採用＝Claude（画像入力対応）」を確定、DEC-D02 で採用モデルの tier（`claude-opus-4-8` `[仮]`）を未決としていた。
- **決定が必要な理由**: (1) モデル tier（DEC-D02）が未確定のままでは EXT-01 の契約・プロンプト設計・運用コスト見積が固まらない。(2) 個人開発かつ日次利用（毎日2〜3食の撮影）のため、**精度だけでなく応答速度と従量コスト**が UX/運用を左右する。(3) 単一プロバイダ固定（Claude直接）は、モデル変更のたびにコード・IF改修が要る。
- **制約**: サーバ側からのみ呼び出し（APIキー非露出）。無料枠中心の運用コスト方針。画像入力＋構造化出力に対応すること。

## 選択肢（Options / Alternatives）
> 📝 ここに検討した案を記載（採用案・却下案の両方）。{案／概要／長所／短所}

判断材料として、2026-07-18 に Artificial Analysis「Vision」リーダーボード上位10モデルを **実測ベンチ**した（外食チェーン23件＋家庭料理10件の正解付き画像、Vercel AI Gateway 経由・全モデル同一プロンプト/同一 zod スキーマ）。根拠データ: `../../poc/food-vision/results/report.md`（外食）・`viz-gemini-3.5-flash.html`・`viz-homecooking.html`。

| 案 | 概要 | 長所 | 短所 |
|---|---|---|---|
| A | Claude API 直接（Anthropic Messages API・`claude-opus-4-8`） | 当初想定。単一プロバイダで単純 | プロバイダ固定でモデル変更にコード改修。opus は実測未検証で高単価。応答も遅め |
| **B（採用）** | **Vercel AI Gateway 経由・既定 `google/gemini-3.5-flash`（reasoning: high）** | **1キーで全プロバイダ、モデルは設定値。実測で外食 総合MAPE 14.7%（精度3位）・応答6.3秒（最速級）・$0.01/枚（最安級）・AA Vision リーダーボード1位。フォールバックで他モデルへ即切替** | Gateway が単一障害点。Vercel への依存。家庭料理は 18.8%（6位）とやや落ちる。脂質は 32.7% と弱い |
| C | Gateway 経由・既定を高精度モデル（`google/gemini-3.1-pro-preview` 外食総合1位=12.2% ／ `openai/gpt-5.6-sol` 家庭料理1位=11.9%） | 総合精度は最上位（Flash比 +2.5pt） | Pro は応答8.0秒・$0.22（**Flashとほぼ同コスト**）だが日次で +1.7秒。Sol は 64.5秒・約10倍コストで日次利用に不適 |

## 決定（Decision）
> 📝 ここに採用案と、具体値・方式を実装が迷わない粒度で記載。{採用案／確定した具体値・方式}

案 **B** を採用する。

- **AI基盤**: 全 LLM 呼び出しを **Vercel AI Gateway** 経由に統一する。エンドポイントは OpenAI 互換（`https://ai-gateway.vercel.sh/v1`）、認証は `Authorization: Bearer <AI_GATEWAY_API_KEY>`。
- **既定モデル**: `google/gemini-3.5-flash`（reasoning: high。`providerOptions.google.thinkingConfig` で指定）。モデル ID は `provider/model` 形式の**設定値**として扱い、コードにハードコードしない。
- **構造化出力**: AI SDK（`ai` パッケージ）の `generateObject` ＋ zod スキーマで受ける。FEAT-08 の出力スキーマは実測済みの `{ food_name, dish_names[], calories_kcal, protein_g, sugar_g, fat_g }` を基線とする（`dish_names` は写真内の複数料理を列挙。単品は1件）。
- **フォールバック**: `providerOptions.gateway.models` に代替モデル（例: `google/gemini-3.1-pro-preview`。精度重視の上位モデル）を宣言し、既定モデルの失敗・レート制限（429）時に切替える。※これは Gateway 背後のモデル切替であり、Gateway 自体の障害には別の縮退が必要（影響・参照）。
- **認証情報**: `AI_GATEWAY_API_KEY` はサーバ環境変数（Secrets）に保管。クライアント・リポジトリに置かない🔒。

## 根拠（Rationale）
> 📝 ここになぜその案かを記載。トレードオフ・却下理由を明示する。{選定理由／却下した案の理由}

- **実測に基づく選定**: Gemini 3.5 Flash は外食で kcal 5.7%／たんぱく質 10.5%／糖質 9.8%（n=10）／脂質 32.7%（総合14.7%・3位）、家庭料理は総合18.8%（6位）。**FEAT-08 は毎日複数回の日次操作**のため応答速度と従量コストを最優先し、最速級 6.3秒・最安級 $0.01/枚で AA Vision リーダーボード1位の Flash を既定に採る。
- **却下した高精度案（C）との正直なトレードオフ**: 1位 Gemini 3.1 Pro は外食12.2%（Flash比 **+2.5pt**）だが応答8.0秒（**+1.7秒**）・$0.22（**Flashとほぼ同コスト**）。2位 GPT-5.6 Sol は家庭料理最良（11.9%）だが応答64.5秒・約10倍コストで日次利用に不適。**「精度+2.5pt より日次の待ち時間 1.7秒短縮を優先」**という判断で Flash を採用する（コスト差はほぼ無いため理由は速度）。実運用で精度不足が判明すれば Pro を既定へ昇格する（再検討条件・参照）。
- **プロバイダ非依存化**: Gateway により「Claude確定（DEC-B01）」を**プロバイダ固定からモデル設定化へ緩和**する。Claude・GPT・Gemini を同一 API で扱え、精度要件が変われば設定変更のみで切替でき、Claude も同 Gateway 経由でフォールバックに使える。DEC-B01 の意図（AIの活用）は損なわない。
- **却下理由**: 案A（Claude直接）はプロバイダ固定・コード改修依存・opus 未検証・高単価。

## 影響（Consequences）
> 📝 ここに決定がもたらす影響を記載。{反映先ドキュメントの該当箇所／関連テスト観点／前提が崩れた場合の再検討条件}

- 反映先:
  - 本 worktree（設計層・design-pr1）: `05_技術選定.md`（AI行・共通スタック・DEC台帳）／`04_外部連携.md`（EXT-01 のプロトコル・認証・要点・DEC台帳）／整合のため `01_構成要素.md`・`02_境界.md`・`03_データフロー.md`・`20_インフラ設計/01・02` の Claude/Anthropic 表記も AI Gateway に更新
  - 【別ブランチ・波及】`docs-func-req`: FEAT-08・（あれば）EXT-01 要件の AI 記述を「Gateway経由・既定Gemini」に更新／`docs-estimate`: `06_概算見積もり.md` の従量費を Gemini 3.5 Flash 単価（入力 $1.5・出力 $9 per 1Mトークン）で再算定（opus 前提より大幅減の見込み）
  - 未作成（後続設計PR）: `30_データ・IF設計/02_API設計.md` で EXT-01 契約を Gateway（OpenAI互換）形式に定義
- 関連テスト観点: TC-（構造化出力スキーマの型・必須項目検証／栄養値の妥当域＝Atwater整合／Gateway の 429〈レート制限〉・402〈残高〉時のリトライ・フォールバック挙動）
- **運用上の前提・リスク（実測から明示）**:
  - **単一障害点**: フォールバックは Gateway 背後のモデル切替に過ぎず、Gateway 自体の障害は救えない。Gateway 不達時はメニュー提案／写真計算を一時不可とし記録・閲覧は継続する（縮退方針は `20_インフラ設計/02_IaC・デプロイ・可用性配置.md`。旧「Claude不達時」を AI Gateway に更新済み）。
  - **課金前提**: AI Gateway はホスティング/DB（無料枠）と異なり**従量課金**。無料クレジットは約$5相当（対象モデル限定・要カード登録）で、本ベンチ1回で既に $7.72 を消費した。日次 2〜3枚（月60〜90枚）なら Flash 単価で月$1未満の見込みだが「無料枠で足りる」とは断定せず、`06_概算見積もり.md` で定量化し、無料枠/レート制限の超過を再検討トリガとする。
  - **精度の弱み**: 脂質 MAPE 32.7% は上位5モデル中で最悪（揚げ物・ドレッシング等の見えない油）。体組成用途では脂質誤差が効くため実運用でモニタし、許容外なら Pro 昇格またはユーザ補正UIを検討。糖質は n=10 の小標本評価である点も留意。
  - **標本の限界**: 本決定の根拠は外食23件＋家庭料理10件＝33枚（収集済み220件のサブセット）。個人開発の一次判断として採用するが、量産前にベンチ拡張で再確認する。
- 前提が崩れた場合の再検討条件:
  - Gemini 3.5 Flash の精度が実運用で許容外（栄養誤差が実用に耐えない）→ 案C の高精度モデル（まず Gemini 3.1 Pro）へ既定変更を再検討
  - Vercel AI Gateway もしくは当該モデルの提供終了・大幅値上げ／vision・構造化出力の劣化
  - **`reasoning: high`（thinkingLevel）依存**: 実測の精度・応答6.3秒・コストは thinking 有効が前提（出力トークンは推論が支配的）。thinking 設定・挙動の変更で3指標が連動して変わるため、モデル更新時は再ベンチする
- **スコープ外（引き継ぐ懸念）**: DEC-D04（食事写真の外部送信・保持ポリシー）は本ADRの対象外。ただし Gateway 経由でも「写真が外部プロバイダへ送信される」事実は変わらず、フォールバック時は送信先プロバイダが変わり得る（実測では既定が Google/Vertex 経由、代替に OpenAI）。データ保持・学習拒否（ZDR / Disallow prompt training）は**利用し得る各プロバイダについて個別に**確認が必要で、これを DEC-D04 の検討材料として引き継ぐ。
