## 背景・課題（Context）
> 📝 ここに何を・なぜ決める必要があるかを記載。関連する要件ID（FEAT/NFR/DM/IF/ST/ERR）を明記する。{決定が必要な理由／制約／前提}

- **対象要件**: FEAT-08（食事撮影タンパク質計算）・SCR-04・EXT-01・NFR-AVAIL-05。
- **AI が返した栄養4項目を、記録前に手で直せるようにするかが未定だった。**
- FEAT-08 §7 は手修正可を `[仮]` としていた。要件側に明記が無い。
- PoC の実測誤差（MAPE・ADR-0001）を判断材料とした。

| 項目 | 誤差（MAPE） |
|---|---|
| カロリー | 5.7% |
| タンパク質 | 10.5% |
| 糖質 | 9.8% |
| **脂質** | **32.7%** |

- 脂質の誤差は大きい。揚げ物やドレッシングの油は写真から見えない。
- `10_GeminiAPI連携.md` は「AI失敗時は手入力で記録できる」を縮退の前提としていた `[仮]`。
- **前提**: 現設計で使うのはタンパク質のみ（RULE-002・RULE-005）。

## 選択肢（Options / Alternatives）
> 📝 ここに検討した案を記載（採用案・却下案の両方）。{案／概要／長所／短所}

| 案 | 概要 | 長所 | 短所 |
|---|---|---|---|
| A | 全項目を手修正できる | 誤差を利用者が直せる | 利用者は正しい値を知らない。直しようがない |
| B | タンパク質だけ手修正できる | 使う項目だけに絞れる | 同上。知らない値は直せない |
| **C（採用）** | 手修正しない。手入力の経路も持たない | 画面が単純。誤差は撮り直しで減らす | **AI が失敗すると、その食事は記録できない** |

## 決定（Decision）
> 📝 ここに採用案と、具体値・方式を実装が迷わない粒度で記載。{採用案／確定した具体値・方式}

案 **C** を採用する。解析結果は**表示のみ**とする。

| 項目 | 内容 |
|---|---|
| 解析結果の表示 | 数値は読み取り専用。入力欄（`TextFormField` 等）にしない |
| 操作 | **［記録する］と［撮り直す］の2つだけ** |
| 手入力の経路 | **持たない。** 栄養値だけを入力して記録する画面を作らない |
| 保存する値 | AI が返した栄養4項目をそのまま保存する |
| 値の由来 | すべて AI 推定になる。`meal_logs` に由来列を追加しない |
| 値がおかしいとき | 撮り直して再解析する |
| **AI が失敗したとき** | **その食事は記録できない。** 撮り直すか諦める |

- ［撮り直す］は撮影からやり直す。角度・明るさを変えて精度を上げる。
- 保存時の値検証は DB の CHECK（非負）だけで足りる。画面側の数値検証は不要になる。

## 根拠（Rationale）
> 📝 ここになぜその案かを記載。トレードオフ・却下理由を明示する。{選定理由／却下した案の理由}

**採用理由（中心）**

- **利用者はタンパク質量を知らない。それを知るために写真を撮る。**
- よって**手入力は代替手段として成立しない。** 直す元になる正しい値が手元に無い。
- 誤差を含んだ値をそのまま記録するより、**撮り直して精度を上げる方が筋が通る。**
- 「明らかにおかしい」の判断は写真と数値の対でできる。撮り直しは利用者が選べる。

**その他の理由**

- 手修正を認めると、記録値が AI 推定か手入力かを区別できなくなる。
- 区別できないと ADR-0001 の精度モニタリングが成り立たない。由来列は追加しない方針である。
- 入力欄が無いぶん画面が単純になる。保存時の検証も減る。

**却下理由**

| 案 | 却下理由 |
|---|---|
| A（全項目） | 直せるという体裁だけを与える。実際には正しい値を持っていない |
| A（全項目） | 記録値の由来が混ざり、精度の評価ができなくなる |
| B（タンパク質のみ） | 同じ理由。使う項目に絞っても、知らない値は直せない |

## 影響（Consequences）
> 📝 ここに決定がもたらす影響を記載。{反映先ドキュメントの該当箇所／関連テスト観点／前提が崩れた場合の再検討条件}

### 1. AI が失敗したとき、その食事は記録できない

- 撮り直すか諦めるかの2択になる。**手入力での救済は無い。**
- 対象は `ERR-AI-*` 系すべて（不達・5xx・レート上限・タイムアウト）。

### 2. NFR-AVAIL-05 との差分（🟡 中）

| 項目 | 内容 |
|---|---|
| 同要件の記述 | AI 不達時は AI 機能を一時不可とし、**記録・閲覧は継続する** |
| 食事記録の実態 | AI が失敗すると、その食事は**記録できない** |
| 影響を受けないもの | トレーニング記録（FEAT-04）・過去記録の閲覧・FEAT-09 の残量表示 |
| 判断 | 要件全体は崩れない。ただし**要件の文言が実態と合っていない** |
| 要るもの | **要件側の見直し。**「記録は継続」の範囲を機能別に書き分ける |

- ⚠️ 要確認（人間判断）: NFR-AVAIL-05 の文言を、食事記録を除く形へ改訂すること。

### 3. 撤回する記述

- `[仮]` で置いていた「**AI失敗時は手入力で記録できることを縮退の前提とする**」は**すべて撤回**する。
- 対象は `10_GeminiAPI連携.md`（§1 の縮退前提・§4 の論点#5）と FEAT-08（§2・§6・§7・§9）。
- FEAT-08 の受入基準にある「手修正して記録する」「手入力での記録は継続できる」も書き換える。

### 4. 脂質の扱い

- **脂質の誤差 32.7% がそのまま記録に残る。** 補正の手段は持たない。
- ただし現設計で使うのはタンパク質のみ。残量（RULE-002）と不足分（RULE-005）に脂質は入らない。
- 表示には精度の注記を添える（FEAT-08 §7）。数値の性質を利用者に伝える。
