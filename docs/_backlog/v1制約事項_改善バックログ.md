# v1 制約事項・改善バックログ

> **方針**: 成果物は **60点でよく、開発で使いながら都度ブラッシュアップ**する前提。**とにかく早く水道の詳細設計に入る**ことを優先し、v1では下記を意図的に割り切った。改善候補は本書に記録し、必要になった時点で着手する。
> **記録日**: {初版}／ PR #1。

## 1. 運用の前提（v1で必要な設定）
| 前提 | 内容 | 誰が |
|---|---|---|
| **main ブランチ保護** | main への merge は **PR＋メンバー承認＋CI通過 必須**。＝**「mainにマージ済み＝承認済み」をシステム的に成立**させる（承認印は手書きしない・履歴は PR/git）。 | リポ管理者が1回ON |
| 共通プラグイン有効化 | `.claude/settings.json` で aic-harness を有効化（規約・エージェント憲法・要件レビュー） | クローン時 |

## 2. v1の制約事項（意図的な割り切り）
| # | 制約 | v1での状態 |
|---|---|---|
| C1 | **設計一式が重い**（DDD/インフラ/帳票/画面モック等）。小規模案件には過剰 | 網羅＋適用マトリクスの「該当なし」で運用（器は全部残る）。プロファイル無し |
| C2 | **RED母集合が1ファイル** | 分割"指針"は明記済／実分割はしない |
| C3 | **統制系と説明系が同居**（00に適用マトリクス/設計着手／ADRは設計配下） | 現配置のまま |
| C4 | **数字プレフィックス採番**が位置依存（挿入で参照玉突きの恐れ） | NN_連番のまま（参照はできるだけID/ファイル名で） |
| C5 | **規約がプラグイン依存**（未導入環境で AGENTS.md 規約が不可視） | プラグイン前提。スナップショット未同梱 |
| C6 | **状態ST-/遷移TR- の二系統**・設計側独自ID（NFR-/DM-/DEC-/TC-/REQ-/KPI-）はハーネス観点外 | 文書化済み（対応不要・記録のみ） |

- 記法をハーネス(aic-harness/criteria.json)準拠へ統一（`FEAT-/ST-/TR-/ERR-/SCR-/RPT-/EXT-/RULE-/TASK-`・`[AC] G/W/T`・sentinel・未決オーナー/フェーズ）。

- example参照の安定URL・DB物理にER図・概要↔As-Is/体制の重複排除リンク（メンバー指摘）。
