# 適用マトリクス（必須／任意／該当なし）

> **目的**: 本プロジェクトで **どの設計ドキュメントを作るか** を宣言する（＝完全性の統制の「入口」）。テンプレの **既定（必須/任意）** をベースに、本PJの **適用** と、作らない場合の **該当なし（理由）** を記録する。**出口**は `../_backlog/リリース承認基準_テンプレート.md` のドキュメントゲートで本表を照合する。
> **書き方**: 「既定=必須」は原則すべて適用。判断が要るのは「既定=任意」の行と、例外的に必須を落とす行。**「該当なし」は必ず理由を書く**（監査で「抜け」と「意図的除外」を区別するため）。「既定=必須」を「該当なし」にする場合は**強い理由＋承認者**を明記する。

## 凡例
- **既定**: テンプレ標準の推奨（`必須` ／ `任意`）。
- **本PJ適用**: `適用`（作る） ／ `該当なし`（作らない・理由必須） ／ `保留`（判断中）。

## 完全性判定の単位（L1固定 / L2展開）
大規模時は BC・機能がリーフとして増える（→ `../ドキュメント構成ツリー.md` の「大規模時の展開規約」）。**個々のクラス/リーフは列挙せず**、次の単位で完全性を判定する。

| 層 | 対象 | 宣言方法 | **判定単位** |
|---|---|---|---|
| **L1 固定文書** | 標準の文書（下表） | 本表で 必須/任意/該当なし を**個別列挙** | **ファイル/フォルダ単位** |
| **L2 展開・BC**（G1） | ドメイン設計のBC群 | 末尾 YAML の `bounded_contexts.list` に**BC名を宣言** | **BCフォルダ単位**（必須構成が揃えば完全。クラスは対象外） |
| **L2 展開・機能**（G2） | 機能別概要 | 末尾 YAML の `features.required` に**FEAT-IDを宣言** | **FEAT単位**（各必須FEATに `01_機能一覧/{FEAT}_*.md`） |

> **CI監査**: 末尾の「完全性マニフェスト（YAML）」を **GitHub Actions が正**として、L1/L2 をファイルシステムと突合する（詳細仕様＝`../_backlog/09_開発プロセス/完全性監査CI_仕様.md`）。人間向けの下表と YAML は同一ファイル内に同居させ、二重管理を避ける。

## 完全性マニフェスト（GitHub Actions が正とする宣言）
> **これがCI監査の正本**。上の人間向け表と内容を一致させる（乖離もCIで検出）。BC・機能は**ここに一覧を宣言するだけ**でよく、個々のクラス/リーフは列挙しない。パスはリポジトリ相対。

```yaml
completeness:
  # L1: 固定文書（必須=適用のものが存在すること）
  fixed_required:
    # - 00_プロジェクト概要/01_プロジェクト概要_人間向け.md
    # - 01_要件定義/01_全体像/01_目的・対象・システム概要.md
    # - 02_設計/60_テスト設計/02_RED母集合_受入基準・状態・エラー.md
    # …（本PJ適用=適用の固定文書パスを列挙）
  fixed_not_applicable:            # 既定=必須を落とす/任意を作らない（理由必須）
    # - path: 02_設計/50_詳細設計/04_移行設計.md
    #   reason: 新規構築でデータ移行なし
  # L2-G1: BC展開（BCフォルダ単位で判定。クラスは列挙しない）
  bounded_contexts:
    base: 02_設計/30_データ・IF設計         # BCサブフォルダの親
    required_files: [マクロ設計.md, データモデル.md, Domain_Event.md]  # 各BCに必須
    list: []                        # 本PJのBC名。例: [auth, billing, contract]。空=BC展開なし（データモデル.md 1枚で足りる小規模）
  # L2-G2: 機能展開（FEAT単位で判定）
  features:
    spec_glob: 01_要件定義/02_機能要件/01_機能一覧/{FEAT}_*.md   # 機能別概要の置き場
    required: []                    # 本PJの必須FEAT-ID。例: [FEAT-01, FEAT-02]。空=1ファイルに集約
```

**CIが検査すること**（`../_backlog/09_開発プロセス/完全性監査CI_仕様.md` に詳細）:
1. `fixed_required` の各パスが存在する
2. `fixed_not_applicable` の各項目に `reason` がある（かつ存在を要求しない）
3. `bounded_contexts.list` の各BCが `base/{BC}/` に `required_files` を全て持つ
4. `features.required` の各FEATに `spec_glob` 一致ファイルが存在する
5.（任意）`base` 直下の宣言外BCフォルダ＝孤児を警告
