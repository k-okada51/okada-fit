# 設計着手チェックリスト（実装＝TDD着手の可否ゲート）

> **目的**: 実装（TDD）に入れる状態かを1枚で判定する **G2設計凍結の実務ゲート**。未決の詳細は再掲せず **`01_要件定義/01_全体像/05_未決定事項.md`（台帳）・ADR を ID参照**（台帳と重複しない）。本書は「着手可否」と「アクション」だけを持つ。
> **書き方**: 各行を ✅/☐ で。外部IF(§3)は実確定が無くても **スタブ合意**なら着手可＝条件付きGo。RED源泉・内部ADR・データ基盤(§1/2/4)が未確定なら No-Go。記入例は example-suido-fax/00_プロジェクト概要/05_設計着手チェックリスト.md 参照。
